# Перенос элементов

Плагин Revit 2022: смена уровня у выбранных элементов без потери расположения.

## Зачем

Уровень элемента поменять несложно — сложно после этого вернуть элемент туда, где он стоял.
Меняешь у стены «Зависимость снизу» с «Этаж 1» на «Этаж 2» — и стена уезжает вверх на разницу
отметок. Дальше вручную: посчитать разницу, вписать её в «Смещение снизу», проверить верх,
и так на каждом элементе.

Плагин делает это за один шаг: уровень меняется, смещение от него пересчитывается, элемент
остаётся на прежних отметках.

## Как пользоваться

1. Выделить элементы в проекте.
2. Вкладка «Перенос элементов» → кнопка «Перенести».
3. Выбрать уровень, на который переносим. Для стен и колонн — при необходимости верхний уровень.
4. «Готово».

## Как устроен перенос (важно)

Единого параметра уровня в Revit нет: у стены это «Зависимость снизу», у колонны «Базовый
уровень», у перекрытия «Уровень», у трубы «Базовый уровень», у балки «Опорный уровень». Все
известные варианты собраны в `Core/LevelBinding.cs`, и у элемента берётся первый подошедший.
Геометрические параметры идут в списке раньше спецификационных — иначе у стены нашёлся бы
«Уровень для спецификации», а сама стена осталась бы на месте.

Компенсация **не вычисляется по формуле** «разница отметок уровней». Причина в том, что уровень
влияет на геометрию по-разному: перекрытие уезжает на всю разницу, элемент с уровнем «только для
спецификации» не двигается вовсе, у балки положение задают отметки концов. Формула в этих случаях
не вернула бы элемент на место, а увела бы его.

Поэтому порядок такой: снять положение → сменить уровень → **замерить, куда элемент фактически
уехал** → вернуть его смещением от нового уровня → сверить. Замер идёт по точке привязки
(`Location`) и по верху габарита; допуск — 0,1 мм.

Если штатного смещения у элемента нет или его не хватило, элемент двигается целиком через
`ElementTransformUtils.MoveElement`.

Габарит целиком в сверке не участвует намеренно: у стены он «дышит» по горизонтали от
присоединений к соседям, а те при смене уровня рвутся — сверка по габариту откатывала бы
корректные переносы.

## Верхний уровень

Второй список в окне — для семейств на двух уровнях: стены, колонны, лестницы, трубы. Верх
возвращается на прежнюю отметку тем же способом, что и низ, — через верхнее смещение.

Двигать элемент целиком ради верха нельзя, это увело бы обратно уже выправленный низ. Поэтому у
элемента без параметра верхнего смещения верх остаётся там, куда его поставил Revit, и сверка
такой перенос откатит.

Если верхний уровень не указан, а элемент опирается на два, перенос одного низа обычно
проваливается: у стены с базой «Этаж 1» и верхом «Этаж 2» перенос базы на «Этаж 2» даёт нулевую
высоту. В отчёте такой случай подписан прямо: «укажите верхний».

## Что не переносится

Элемент, который нельзя перенести без сдвига, **остаётся на прежнем уровне**: его подтранзакция
откатывается целиком, остальные элементы это не задевает. Все такие случаи перечислены в отчёте
с причиной, и кнопка «Выделить в проекте» переносит на них выделение.

Причины, которые встречаются:

| Причина | Что это значит |
|---|---|
| у элемента нет параметра уровня | аннотация, марка, элемент на рабочей плоскости |
| параметр только для чтения | размещён на грани, внутри группы или закреплён |
| уже на этом уровне | менять нечего |
| расположение не сохранилось, сдвиг N мм | вернуть на место не удалось, перенос отменён |
| Revit отклонил перенос | элемент не допускает такую комбинацию уровней |

Отдельно: элементы внутри групп Revit редактировать поштучно не даёт — их надо переносить
редактированием самой группы.

## Установка

```
powershell -ExecutionPolicy Bypass -File install.ps1
```

Скрипт собирает проект и кладёт манифест в `%AppData%\Autodesk\Revit\Addins\2022`.
Revit при этом должен быть закрыт — он держит DLL загруженной.

## Сборка

```
dotnet build src\LevelMover\LevelMover.csproj -c Release
```

Нужен Revit 2022 в `C:\Program Files\Autodesk\Revit 2022\` — оттуда берутся `RevitAPI.dll`
и `RevitAPIUI.dll`. Другой путь задаётся свойством `RevitDir`.
